## 📊 系统架构

### 模块依赖关系

```
start_auto_reply.py (菜单启动)
    ↓
auto_reply_controller.py (主控制器)
    ├─ keyword_matcher.py (关键字匹配) ✓
    ├─ dynamic_locator.py (动态定位) ✓ 核心！
    ├─ auto_reply_engine.py (自动回复) ✓
    └─ 实时评论监听提取工具.py (评论提取) ✓
```

### 完整工作流

```
START (用户按 Enter)
  ↓
[1] 收集评论 (15-20 秒)
    └─ 加载并提取评论
  ↓
[2] 匹配关键字 (1-2 秒)
    └─ 找出需要回复的评论
  ↓
[3] 自动回复 (1-3 分钟)
    ├─ 动态定位评论位置 ⭐
    ├─ 点击评论
    ├─ 输入回复文本
    ├─ 发送回复
    └─ 自动重试 (失败时)
  ↓
[4] 生成报告 (1 秒)
    └─ 统计结果，保存 JSON
  ↓
END (显示统计)
```

## 🔐 防封号机制

### 内置安全措施

```python
# 1. 回复间隔 (3 秒/条)
wait_between_replies = 3

# 2. 最多回复数 (20 条/个视频)
max_replies = 20

# 3. 智能重试 (失败自动重试)
max_retries = 3

# 4. 操作延迟 (点击、输入、发送之间都有延迟)
time.sleep(1.5)  # 点击后等待
time.sleep(0.5)  # 输入后等待
time.sleep(2)    # 发送后等待
```

### 推荐使用方式

```
单个视频: 最多 15-20 条回复
多个视频: 每个视频之间等待 10 秒以上
每天: 不超过 100 条回复
```

## 🆘 故障排除

### 常见问题快速解答

**Q: 评论找不到怎么办?**
A: 系统会自动滑动寻找，最多尝试 3 次。如果仍未找到，说明评论不在当前流程范围内。

**Q: 回复失败了怎么办?**
A: 系统会自动重试，最多 3 次。如果仍失败，会记录在报告中。

**Q: 可以加快速度吗?**
A: 不建议。当前的 3 秒间隔是最佳的防封号配置。

**Q: 回复内容会暴露吗?**
A: 你可以自定义回复内容，看起来像真人回复。
