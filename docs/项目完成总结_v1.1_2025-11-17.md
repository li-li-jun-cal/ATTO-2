```
  ↓

  │   - 逐个评论匹配
  │   - 提取匹配结果
```

## 🎯 核心技术点

### 1. 动态定位 ⭐ (最关键)

**问题**: 坐标在滑动和界面更新后会失效

**解决方案**: 实时 UI 层级查询
```python
# 不依赖缓存坐标，每次都查询最新位置
def find_comment_by_text(self, target_text):
    xml = device.dump_hierarchy()  # 获取最新 UI 树
    for element in parse_ui_tree(xml):
        if target_text in element.text:
            return get_center_coordinates(element.bounds)
```

**优势**:
- ✅ 永远准确，不依赖历史坐标
- ✅ 自动处理界面变化
- ✅ 不受滑动影响

### 2. 关键字匹配

**实现**: 正则表达式 + 模板系统
```python
# 支持自定义关键字和回复文本
matcher = KeywordMatcher(keywords_file='my_keywords.json')
matched = matcher.match_comments(comments)
```

**特性**:
- ✅ 默认 10 个常用关键字
- ✅ 支持自定义关键字和回复
- ✅ 灵活的匹配逻辑

### 3. 自动重试机制

**实现**: 指数退避 + 智能重定位
```python
for attempt in range(1, max_retries + 1):
    result = try_reply()
    if result['success']:
        return result
    time.sleep(2 ** attempt)  # 指数退避
    location = locator.find_comment()  # 重新定位
```

**特性**:
- ✅ 最多重试 3 次
- ✅ 每次重试都重新定位
- ✅ 指数退避延迟

### 4. 防封号保护

**机制**:
```
• 回复间隔: 3 秒/条 (固定)
• 最多回复: 20 条/视频 (推荐)
• 智能延迟: 点击、输入、发送都有延迟
• 动态定位: 避免频繁点击错位置
```

```

避免:
  ✗ 一次性回复 100+ 条
  ✗ 快速连续操作多个视频
  ✗ 频繁修改关键字和回复内容
```

## 🐛 已解决的问题

### 问题 1: API 兼容性
**原因**: uiautomator2 v3.0+ 改变了 API
**解决**: 使用 polling loop 替代 `.wait.exists()`

### 问题 2: 元素遍历
**原因**: 所有评论使用相同 ID
**解决**: 使用索引而非 ID 遍历元素

### 问题 3: 坐标缓存失效
**原因**: 坐标在滑动后失效
**解决**: 实现 DynamicLocator，每次查询最新坐标

### 问题 4: 评论区打不开
**原因**: 不知道需要点击才能打开
**解决**: 实现 `_open_comment_section()` 方法，包含 3 种策略

### 问题 5: 稳定性不足
**原因**: 单点失败导致整个流程失败
**解决**: 加入自动重试机制和多个备选方案
